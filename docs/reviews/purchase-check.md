# 買う前チェック：プロダクトレビューと検証

2026-10-05。対象は develop c273a66 を基点にした変更。

## 現状の厳しい評価

- 一行入力、OCR、音声、カテゴリ、予算、カレンダー、集計は充実しているが、記録の後に行動を変える導線が弱い。
- AIの短い感想や回数制限の解除だけでは、買い切りを選ぶ理由として弱い。特にAI非対応端末で価値が減る。
- 銀行連携を増やすだけでは大手との機能競争になる。ローカル処理という既存の利点を保ち、買う前の判断を支援する。
- 「世界初」「課金率が上がる」とは主張できない。継続利用・支払意思はTestFlightで検証すべき仮説。

既存サービスの公式説明も確認した。Zaimは予算・支出の比較を提供し、YNABにはWish Farmがある。単なる残額表示や欲しい物リストだけを差別化とは扱わない。

## 今回の体験

ホームの「買う前チェック」から金額と月末まで残しておく額を入力。無料で「見送る」「買う」の予算残り・1日あたりを比較。固定費の内訳を展開できる。予算が未設定ならその場で設定できる。

過去28日の支出から、明日から月末までの支出見込みも表示する。プレミアム・無料体験では、繰り返したカフェ・娯楽を何回減らすか操作し、買い物後の月末の余裕を比べられる。計算は端末内の決定的なコード。AIの有無によらない。

これは試算であり、支出の登録・変更や節約の実績の保存はしない。入力は画面を閉じると消える。記録やスキーマの移行、通信先の追加はない。

## 視覚化

金額は同じ尺度の比較バーで表示し、赤字はゼロ線の左へ伸ばす。支出・固定費・残す額・使える額は色分けの帯にする。プレミアムの組み替えは品目のアイコンと回数で操作し、購入額に対する比率を円形の進捗で示す。計算の長い説明は「計算に使った記録」に折りたたむ。色だけに頼らず、記号・数字・VoiceOverラベルを併記する。大きい文字では比較の見出しと金額を縦に積み、装飾用のアイコン列は幅を増やさない。

## レビューで守る条件

- 予算から今月の記録済み支出（未来日も）と、未記録の固定費を先に引く。収入は足さない。
- 残しておく額は予算からさらに確保。負の残額を0にして隠さず、日割りの目安だけ0で止める。
- 節約見込みを未消費の予算に足さない。組み替えは将来の支出見込みだけを減らす。
- 履歴は昨日までの最長28暦日。7日以上に支出があり、最初の記録が14日以上前でなければペースを推定しない。分母は最初の記録の日から昨日までにし、利用開始前を支出ゼロに数えない。期間内の未記録日は0として扱うことを画面で明示。
- 初日に無料体験を始めると、履歴条件が揃うのが体験終了直前になる。購入不要の操作できるサンプルを購入画面と履歴不足時に置き、個人の履歴が揃ってから体験を始めることを案内する。サンプルは本体と同じ計算を使い、記録・予算・体験の状態を変更しない。
- 自動記録された固定費と収入は履歴のペースから除外。未来日の支出は先に確保し、日々の支出とは別の追加予定として扱う。手動で記録した固定費は自動では識別できない。
- 今日の追加支出は見込みに含めない。口座残高や「買ってよい」という保証ではない。
- 減らす候補はカフェ・娯楽のみ。同じ品目とカテゴリが3件以上。回数上限は履歴の頻度、額は小さい側の中央値。最大5候補。
- 記録・予算・固定費のどれかを読めなければ試算を消し、再読み込みを案内。読み込み失敗を支出0として扱わない。
- 無料への復帰では組み替え効果を適用しない。基本比較と入力は残す。

## テストとTestFlightで見る点

コア：予算・確保額・過剰支出・不正値・月末・未来日・収入・固定費の二重計上・少ない履歴・中央値・候補の範囲・回数上限。
アプリ：375pt幅・日本語/英語・標準/最大文字で図が横にはみ出さないこと、読み込み失敗と再試行、削除後の候補、月またぎ、無料と体験終了、試算が保存済み記録を変えないこと。
既存のmake ciで全体の回帰・ローカライズ・StoreKit・Releaseアーカイブを検証。画面は日本語・英語・ダーク・大きい文字で確認する。

TestFlightでは、実際の買い物前に使えるか、予算残りと月末の目安の違いを説明なしで理解できるか、候補が本人にとって減らせるものか、組み替え機能への支払意思があるかを聞く。自動計測SDKは追加しない。

未検証の限界：実機でのVoiceOver操作、利用者の支払意思、疎な入力による見込みの精度。これらを自動テスト成功と混同しない。
