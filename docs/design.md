## 1. コンセプト

- **何か**: 直感的に家計簿をつけられる iPhone アプリ。名前は SaifuLog（サイフログ）。
- **入力**: チャットのように「ランチ 850」と一行送るだけで記録する。記録はタイムラインに
  吹き出しで並ぶ。記録も質問も同じ入力欄から行う。
- **売り**: お金のデータを外に出さない。AI も含めて端末内で完結し、開発者のサーバーを持たず、
  家計のデータを端末の外へ送らない（利用者が有効にした iCloud を除く。§5-3）。そのため API 費用も
  かからない。
- **続けやすさ**: 家計簿は入力が面倒になるとやめてしまいやすい。入力を一行にし、分類と
  計算はアプリが引き受ける。

## 2. 入力の設計（ひとこと入力）

検討した案のうち、**案B「ひとこと入力」** と、それを iOS の AI で広げる **案B+** を採用した。

- 入力欄はホームの下に 1 つだけ置く。カメラ・マイク・送信のボタンを並べる。
- 送った一行は吹き出しとしてタイムラインに出し、すぐ「直す」「取り消す」を示す。
  読み違いをその場で直せれば、AI の精度が完璧でなくても使えるため。
- 質問（「今月カフェにいくら？」）も同じ入力欄に打つ。記録か質問かはアプリが見分ける。
  入口を分けると、利用者が「どこに書けばいいか」を考えることになるため。

## 3. 端末内 AI の使い方

AI はすべて Apple の Foundation Models フレームワークで、端末内で動かす。

### 3-1. AI をどこで動かすか

| 観点 | 端末内 AI（Foundation Models） | クラウドの LLM API | ルールベースのみ |
|---|---|---|---|
| データが外に出ない | ◎ | ✕ | ◎ |
| 運用の費用 | ◎ かからない | ✕ 使うほどかかる | ◎ かからない |
| 通信なしで動く | ◎ | ✕ | ◎ |
| 自然な文章の理解 | ○ | ◎ | △ |
| 対応機種の広さ | △ Apple Intelligence 対応機種のみ | ◎ | ◎ |

クラウドは理解力で勝るが、「データを外に出さない」という売りと両立せず、サーバーと
従量の費用も要る。**端末内 AI を主にし、ルールベースを下支えにする**（§4）。

### 3-2. 文章を理解して記録する（ガイド付き生成）

`@Generable` の型を決め、モデルにはその形で値を返させる。自由文を返させて後から
読み解くより、壊れた出力が来にくいため。

| 入力 | 記録のされ方 |
|---|---|
| ランチ 850 | 食費 ¥850 |
| 昨日 焼肉12000 4人で割り勘 | 前日・食費・¥3,000（立て替えた ¥9,000 はメモ） |
| スーパー2480とドラッグ1200 | 2 件に分けて記録 |
| 給料 25万 | 収入 ¥250,000 |

- 割り勘の例では、モデルには「総額 12000・人数 4」を取り出させ、**¥3,000 と ¥9,000 は
  コードで計算する**。端末内モデルは小さく、割り算を任せると間違えることがあるため。
- 「25万」「1万2千」のような単位、全角数字、「昨日」「おととい」のような日付の言い回しの
  正規化もコード（SaifuLogCore）で行う。
- **自信がないときだけ聞き返す。** 毎回確認を挟むと一行入力の軽さが失われるため。
- **利用者の修正を覚える。** 「この言葉はこのカテゴリ」という対応を端末内に残し、次から
  AI への手がかりと、ルールベースの辞書の両方に使う。

### 3-3. レシート・スクショから明細ごとに仕分ける

- iOS 27 で加わった画像入力と、文字認識（OCR）を行うツールを組み合わせ、明細ごとに
  カテゴリを分ける。
- 読み取り結果はホームのタイムライン内にカードとして出し、確認してから確定する。
- 明細の合計とレシートの合計額はコードで突き合わせる（案）。合わないときはカードに印を出す。

### 3-4. 家計に質問する（ツール呼び出し）

- 合計・平均・予算の残りなどを返す `Tool` を用意し、**数字はツール（アプリのコード）が
  計算する。** AI はどのツールを呼ぶかを選び、答えの言い回しだけを作る。
- 計算した数字は、AI の文章とは別に画面にも出す（案）。AI が言い回しの中で数字を
  書き換えても、正しい値が見えるようにするため。

### 3-5. 週のふりかえり

- 1 週間の数字はコードで集計し、AI は短いメッセージにするだけ。
- 無料は簡易版。プレミアムには月の AI レポートと予算の提案がある（§6）。

### 3-6. 後の段階

- 声で記録する（Speech）。
- Siri・ショートカット・アクションボタンから記録する（App Intents）。

## 4. AI の制約とフォールバック

### 4-1. 使えない場面

- **Apple Intelligence 対応機種のみ**（iPhone 15 Pro 以降など）。
- 対応機種でも、Apple Intelligence がオフのときや、モデルのダウンロード中は使えない。
  `SystemLanguageModel.default.availability` で判定する。
- 生成そのものが失敗することもある（安全のための拒否、文脈の長さの超過など）。

### 4-2. 切り替え方

AI が使えないとき、または失敗したときは、**SaifuLogCore のキーワード辞書によるルールベース
解析に切り替える。** AI が無くても記録できるアプリにする。AI は上乗せであって前提ではない。

| 機能 | AI が使える | AI が使えない |
|---|---|---|
| ひとこと入力 | 文章を理解（割り勘・複数件・日付の言い回し） | キーワード辞書で金額・カテゴリ・日付を読む。「ランチ 850」の形は記録できる |
| レシート・スクショ | 画像入力 + 文字認識で明細ごとに仕分け | 未決（§13） |
| 家計に質問 | ツール呼び出しで答える | 未決（§13）。月のまとめ画面で数字は見られる |
| 週のふりかえり | AI が言い回しを作る | 定型文に数字を差し込む（案） |

### 4-3. 読み違いへの備え

- **計算はさせない。** AI は値を取り出すだけ（§3-2）。
- AI が返した金額が入力文の数字から導けないときは、記録せずに聞き返す（案）。
  小さなモデルが数字を作ってしまう場合に備えるため。いまの試作では、その AI の結果を捨てて
  ルールベースで読み直している。
- AI が返した日付の表記と割り勘の人数も、入力と突き合わせてから使う。日付は入力の言い回しが
  指す日と合わなければ入力そのものから読み、人数は入力に割り勘の語と「N人」があるときだけ採る
  （ルールベースと同じく、人数だけでは割らない）。入力に無い数で、保存する金額や日付が
  変わらないようにするため。
- 記録の直後に「直す」「取り消す」を必ず出す。直した内容は覚える。

## 5. アプリとコアの分担

### 5-1. 置き場所

| 置き場所 | 受け持つもの | 入れないもの |
|---|---|---|
| `SaifuLog/`（アプリ本体） | SwiftUI の画面、SwiftData のモデル、Foundation Models の呼び出し、StoreKit | — |
| `Packages/SaifuLogCore/` | 金額・日付の読み取り、キーワード辞書、割り勘や合計・平均・残りの計算、無料枠の数え方 | FoundationModels / SwiftData / SwiftUI |

コアを純粋なロジックに保つのは、CI の macOS ランナーで `swift test` を回せるようにするため。
platforms を `.iOS(.v26), .macOS(.v14)` にして、macOS 側を低く保っているのも同じ理由。
数字の計算がすべてコアにあれば、「AI に計算させない」をテストで守れる。

### 5-2. データモデル（案）

実装時に確定する。ここでは形の見当だけを書く。

| モデル | 主な項目 | 備考 |
|---|---|---|
| 記録 | 日付、金額、種別（支出・収入）、カテゴリ、メモ、入力元（ひとこと・レシート・声）、元の入力文 | 元の入力文を残すと、直すときや解析の見直しに使える |
| 予算 | 月、全体の金額、カテゴリ別の金額（プレミアム） | |
| 覚えた修正 | 言葉、カテゴリ | AI への手がかりと辞書の両方に使う |

- **金額は整数（円）で持つ。** 浮動小数点の誤差を家計簿に持ち込まないため。円以外に
  広げるなら、最小単位の整数と通貨コードを持つ形にする（§13）。
- **最初から iCloud 同期（SwiftData + CloudKit）の制約に合わせる。** 一意制約を使わない、
  プロパティに既定値を持たせる、関係は任意にする。後から合わせるとデータの移行が要るため。

### 5-3. iCloud の将来計画

- 現在は提供しない。提供するときは任意の機能にし、利用者自身の iCloud の私用データベースに
  保存する。開発者は内容を読めない。
- 家族・パートナーとの共有（プレミアム）は、CloudKit の共有の仕組みを使う想定。
  SwiftData 単体で共有を扱えるかは要確認（§14）。
- 導入するときは `PRIVACY.md` と App Store のプライバシー表示を見直す（§11）。
- 無料に入れると決めた「iCloud バックアップ」（§6）を何で実現するかは**未決**（§13）。候補は次の 3 つ。
  v1 に入れるかも決めていない。
  - CloudKit の私用データベースへの任意の同期を、バックアップとして出す（上の同期と同じ仕組み）
  - 記録を書き出したファイルを、利用者の iCloud Drive に保存する（CSV 書き出しの延長）
  - アプリ側では何もせず、iOS 標準のデバイスのバックアップ（iCloud バックアップ）に任せる。
    この場合、料金表の「iCloud バックアップ」はアプリの機能ではなくなるので、表記を見直す

## 6. 収益化

広告は出さない。**無料版でも記録（AI の文章理解を含む）は無制限。** 端末内 AI は
API 費用がかからないので、いちばん使う機能に上限を付ける理由がない。

| 機能 | 無料 | プレミアム |
|---|---|---|
| ひとこと入力・AI の文章理解 | 無制限 | 無制限 |
| レシート・スクショの読み取り | 月5回 | 無制限 |
| 家計に質問 | 月10回 | 無制限 |
| 週のふりかえり | 簡易版 | ○ |
| 月の AI レポートと予算の提案 | ✕ | ○ |
| 予算 | 全体の予算 | カテゴリ別の予算も |
| 家族・パートナーと記録を共有 | ✕ | ○ |
| iCloud バックアップ・CSV 書き出し | ○ | ○ |

- **プレミアムは買い切り ¥1,800。** サブスクにはしない。ファミリー共有に対応する。
- **最初の 14 日間は全機能を無料で開放する。** 支払い情報の登録は求めない。
  - 買い切りの App Store アイテムには、サブスクのような無料体験の仕組みが無い。審査ガイドライン
    3.1.1 が認める「価格 0 の非消耗型アイテム（14 日間の体験）」を使う方式を想定している（§13）。
    端末内の日付だけで数えると、再インストールでやり直せてしまうため。
- **バックアップと CSV 書き出しは無料。** データを人質にしないため。iCloud バックアップの
  実現方法は未決（§5-3、§13）。
- **App Store Small Business Program に加入する**（手数料 15%）。
- 体験が終わったときにプレミアムの案内（⑨）を出す。

## 7. 外観と配色

- **ライトとダークは iOS のシステム設定に従う。** アプリ内に外観の設定は置かない。
  設定項目を増やさず、iPhone 全体の見た目に合わせるほうが自然なため。
- 配色は 3 案で検討中。**未確定。** どの案もライトとダークの両方を用意する。

| 案 | 状態 |
|---|---|
| 和紙 × 藍 | 推奨 |
| ミント | 候補 |
| 夜 × アプリコット | 候補 |

- カテゴリの色（§8）は 3 案で共通にする。配色を変えても、カテゴリの見分け方が変わらない
  ようにするため。
- アプリアイコンは、推奨案の藍を仮の色にした**仮のもの**（藍の地に吹き出しと ¥）を入れてある。
  App Store Connect はアイコンの無いビルドを受け付けず、配色が決まるまで待つと最初のアップロードが
  できないため。配色が決まったら作り直す（§15）。

## 11. プライバシー表示の方針

- App Store のプライバシー表示は「**データの収集なし**」を目指す。端末内の保存と端末内の
  AI の処理は、開発者が受け取らないので「収集」にあたらない。
- 解析や広告の SDK を 1 つでも入れると、表示と `PRIVACY.md` の両方が崩れる。入れない。
- iCloud（CloudKit の私用データベース）も開発者は読めないが、導入するときに表示を見直す。
- `PRIVACY.md` には「端末の外へ送らない」と書き、「通信機能を持たない」とは書かない。
  将来 iCloud を入れる予定と食い違うため。
- `PrivacyInfo.xcprivacy`（UserDefaults の利用理由 CA92.1 など）と記述を合わせる。

## 12. 競合と差別化

| アプリ | 入力の特徴 |
|---|---|
| トーク家計簿 | AI に話しかけて記録する |
| LINEで家計簿 | LINE のトークに「ランチ 800」と送って記録する |
| AIうちの家計簿 | AI によるレシートの読み取りと、家計の相談 |

他社の料金やデータの扱いは変わりうるため、ここでは比較の記号を付けず、入力の特徴だけを書く。

SaifuLog の差別化は次の 3 つ。

1. **端末内 AI で、データが外に出ない。** 開発者のサーバーを持たず、家計のデータを端末の外へ
   送らない（利用者が有効にした iCloud を除く）。
2. **自然な文章をそのまま理解する。** 割り勘・複数件・日付の言い回しを一行で書ける。
3. **買い切り。** サブスクにしない。

| プレミアムの週のふりかえり | 簡易版とどう変えるか |
| 収入のカテゴリ | 給料・その他のように分けるか、分けないか |
| 円以外の通貨 | 英語で使う人に向けて、ほかの通貨を扱うか |
| 家族との共有の方式 | SwiftData と CloudKit の共有をどう組み合わせるか |
| 無料の iCloud バックアップ | 何で実現するか（CloudKit の任意の同期 / iCloud Drive への書き出し / iOS 標準のバックアップに任せる）と、v1 に入れるか（§5-3） |
| App Store のアプリ名 | 日本語のストアでの表記を「サイフログ」にするか「SaifuLog」にするか |

## 14. リスク

| リスク | 内容 | 対応方針 |
|---|---|---|
| 対応機種 | AI は Apple Intelligence 対応機種でしか動かない | ルールベースで記録は必ずできるようにする。AI は上乗せにする |
| 読み違い | 端末内モデルは小さく、文章を読み違える | 計算はコード、自信がないときの聞き返し、直す・取り消す、修正を覚える |
| 数字の作り話 | 質問の答えに、AI が計算していない数字を書く | ツールで計算した値だけを使い、画面にも別に出す |
| OS の新しさ | 画像入力は iOS 27 以降で、対象の iOS 26 では使えない | iOS 26 での代わりを決める（§13） |
| 体験の審査 | 買い切りの体験は、サブスクの無料体験の仕組みを使えない | ガイドライン 3.1.1 の方式に沿い、体験の期間と終了後の内容を事前に示す |
| プライバシー表示 | SDK を 1 つ入れるだけで「データの収集なし」が崩れる | 解析・広告の SDK を入れない |
| iCloud 導入時の移行 | 後からモデルを CloudKit の制約に合わせると、移行が要る | 最初から制約に合わせる（§5-2） |
| 共有の実現性 | SwiftData 単体では CloudKit の共有を扱えない可能性がある（要確認） | 家族との共有に着手する前に検証する |
